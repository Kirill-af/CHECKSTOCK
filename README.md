# CheckStock — тестовое задание

Веб-прототип учёта остатков на складах фулфилмента (ФФ): физический остаток, доступно, резерв FBS, товар в пути между ФФ / на FBO / к клиенту по FBS.

Стек: **Python, FastAPI, PostgreSQL**.

## Быстрый запуск

Нужны Docker и Docker Compose.

```bash
docker compose up --build
```

Открыть: [http://localhost:8000](http://localhost:8000)

API docs: [http://localhost:8000/docs](http://localhost:8000/docs)

Остановка:

```bash
docker compose down
```

Сброс БД (пересоздать seed):

```bash
docker compose down -v
docker compose up --build
```

## Тестовые данные (seed)

Один магазин «Демо-магазин», два ФФ:

| Артикул | Товар      | Север | Юг |
|---------|------------|------:|---:|
| SKU-101 | Органайзер |    10 |  6 |
| SKU-102 | Контейнер  |     5 |  0 |
| SKU-103 | Корзина    |     0 |  4 |

## Что реализовано

### Экран остатков
- По каждому SKU и ФФ: **на складе / доступно / резерв FBS**
- Доступно = на складе − резерв FBS
- Отдельно: в пути между ФФ, FBO, FBS → клиент
- Удалённые ФФ остаются в таблице — видно, где числится товар

### Склады и движения
- Добавление / переименование / удаление ФФ
- Приход, отправка и приёмка перемещений между ФФ
- При удалении ФФ остатки и история **не теряются** (soft delete)

### FBS / FBO
- Резерв FBS блокирует доступный остаток
- Отмена резерва возвращает доступность
- Отправка FBS списывает с ФФ и ставит «в пути к клиенту»
- FBO списывает с ФФ и числится в пути до приёмки на МП
- Нехватка на выбранном ФФ при достаточном общем остатке → `409` с альтернативами

### История и идемпотентность
- Журнал операций: товар, количество, откуда/куда
- Каждая операция требует `idempotency_key`
- Повтор с тем же ключом **не списывает повторно** (`reused: true`)

## Ключевые решения

1. **Остатки на складе** хранятся в `stock_balances` (`on_hand`, `reserved_fbs`).  
   «В пути» — отдельные записи `transit_shipments`, пока статус `in_transit`.
2. **Идемпотентность** через уникальный `operations.idempotency_key`: повтор подтверждения возвращает исходную операцию.
3. **Нехватка на ФФ**: если на выбранном складе мало, а суммарно по активным ФФ хватает — API отдаёт конфликт и список альтернативных складов.
4. **Удаление ФФ** — soft delete: склад неактивен, операции с него запрещены, остатки продолжают отображаться с пометкой «удалён».

## Сценарии для проверки

### 1. Приход
UI → «Приход»: SKU-102 на Юг, qty=3 → остаток Юг становится 3.

### 2. Резерв и FBS
- Резерв FBS: SKU-101, Север, qty=4 → доступно 6, резерв 4
- Отправка FBS: qty=4 → на складе 6, резерв 0, «к клиенту FBS» = 4

### 3. Перемещение между ФФ
- Отправить SKU-101 с Севера на Юг, qty=2 → Север −2, появляется «в пути ФФ»
- Принять в таблице «Товар в пути» → Юг +2

### 4. FBO
- Отправить FBO SKU-102 с Севера, qty=2 → в пути FBO
- «Принять на МП» → путь закрывается

### 5. Нехватка на выбранном ФФ
SKU-103 на Севере = 0, на Юге = 4.  
Резерв FBS на Севере qty=1 → ошибка нехватки и подсказка по Югу.

### 6. Повторное подтверждение
Повторить тот же запрос с тем же `idempotency_key` → `reused: true`, остатки не меняются.

### 7. Удаление ФФ с остатком
Удалить «Юг» → склад помечен удалённым, остатки SKU на нём видны в таблице остатков.

## Локальный запуск без Docker (опционально)

1. Поднять PostgreSQL и создать БД/пользователя `checkstock` / `checkstock`
2. Установить зависимости: `pip install -r requirements.txt`
3. `set DATABASE_URL=postgresql+psycopg2://checkstock:checkstock@localhost:5432/checkstock`
4. `uvicorn app.main:app --reload`
